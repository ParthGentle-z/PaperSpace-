This checklist covers the M1 cloud foundation on the `m1/cloud-foundation` branch. It distinguishes repository/static checks from tests that require a configured Firebase project, Google OAuth client and a real browser.

## Known limitations and release blockers

1. Firebase and Google Cloud resources have not been created or configured in this repository workflow. Live authentication, Firestore and Drive operations cannot work until the user separately configures those services.
2. Notes, highlights, bookmarks and reading positions are still stored locally in IndexedDB; M1.5 only syncs PDF binaries and paper metadata.
3. Firestore security rules have not yet been tested with the Firestore Emulator or deployed.
4. Cross-device restore requires the same PaperSpace/Firebase account and the Google account that owns or has access to the Drive files.
5. A Drive upload can succeed before its Firestore metadata write fails, leaving an unindexed file in the user's Drive. The local PDF remains safe; the user may need to manage that orphaned Drive file manually.
6. Drive folder IDs are cached per browser. On a different browser the app may create another folder named `PaperSpace`; cloud file references remain in Firestore.
7. No billing account, payment method or paid fallback may be added. If any required API stops working on a no-billing basis, stop and report the limitation.

## Release decision

**M1.6 is not fully passed yet.** The repository has static review and a CI build workflow, but the build result and all live integration/regression tests remain pending. Do not merge to `main` or deploy as a production cloud-enabled release until these checks have been run and reviewed.
